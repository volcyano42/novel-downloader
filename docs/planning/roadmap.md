# novel-downloader 发展方向分析

> **来源**：2026-09-27 会话的实勘（GitHub API 查证 + 代码/文档勘察）+ 方向分析。
> **性质**：§1 的现状事实全部**已实测**（依据标注在各条后）；§2 起为**建议**，不是承诺。
> **目标假设**：按「**影响力 / 作品集**」编排路线图。若你的目标不同，见 [§8 取决于你的三个决定](#8-待补充信息取决于你的三个决定)。

## 0. 一页结论

1. **核心架构已经收敛，内部债基本清完**——最近三批大动作全是「向内整理」（v4.5.0 书源扁平化 + 并发重做、v4.5.1 移除 Android 套壳、2026-09-27 `source_name` 全局唯一）。继续做内部重构的边际收益已经很低。
2. **这个项目的真实瓶颈不在代码，在「外部」**：仓库已 public 但 0 star / 无 README / 无仓库描述 / 无 topics / 无 Docker —— 别人打不开、看不懂、装不上。
3. **必须先处理两处认知不一致**（§1.2）：① 主仓库 `novel-downloader` 是 **public** 的，而它含有 `AGENTS.md` 明令「不进 public」的敏感书源与私密文档；② 面向外界的 `novel-crawler` 停在 2026-09-24、落后主仓库数十个提交，还带着已删除的 Android 套壳。
4. **合规上唯一可行的公开形态**：core（引擎/存储/导出/阅读/CLI/WebUI）合法开源，**书源一律外置**，官方只随附公共领域 / 官方开放 API / 用户自有内容三类示范源。项目已有的 `NLD_PRIVATE_SOURCES` 与 `docs/source-plugin.md` 已把这条路铺了 80%。
5. **最高性价比的动作**是「README + 可见性决断 + 修失效的迁移清单 + 一个合规示范源跑通闭环」——半天到两天的工作量，比任何新功能都重要。

### 1.2 两处必须先解决的认知不一致

#### ⚠️ 不一致 A：主仓库是 public 的，而它含有「不进 public」的东西

`AGENTS.md` 的既定判定：「`api` 书源（oiapi/rain）、`app_data`、私有配置、`docs/superpowers`、`AGENTS.md` 一律不进 public」。

但 GitHub API 实测（`GET /repos/volcyano42/novel-downloader`，2026-09-27）：

| 项 | 实测 |
|---|---|
| 可见性 | **public**（创建 2026-04-19，默认分支 `main`，约 24.6 MB） |
| 根目录 | `.github`、`.gitignore`、`.pre-commit-config.yaml`、**AGENTS.md**、CHANGELOG.md、LICENSE、**PUBLIC_MANIFEST.md**、app.py、backend、cli、cli.py、docs、frontend、init_config.py、main.py、novelbase、pyproject.toml、requirements.txt、scripts、shared、template、tests |
| `novelbase/sources/` | `92xs_requests_default`、`fanqie_api_oiapi`、`fanqie_api_rain`、`fanqie_browser_default`、`fanqie_requests_default`、`qidian_browser_default`、`qidian_requests_default`、`qimao_api_rain`、`qimao_browser_default`、`qimao_requests_default` —— **红名单书源一个不少** |
| 曝光度 | **0 star / 0 fork / 0 watcher / 0 open issue / 仓库描述为空 / topics 为空** |

**结论**：「私有源隔离」在 GitHub 上**没有生效**——隔离实际是在第二仓库 `novel-crawler` 上做的，而主仓库虽然 public，一直被当作「私有工作仓库」使用（无 README、无描述、不宣传 → 靠**不被发现**）。这条路现实中能走，但它是**隐蔽性**（security by obscurity），不是隔离：关键词搜索、Star 推荐、爬虫索引都可能命中，而历史提交一旦公开就无法收回。

> 这也说明：文档里说的「private 仓库」与 GitHub 的实际可见性不是一回事，需要在你自己的口径里统一。

#### ⚠️ 不一致 B：面向外界的 `novel-crawler` 严重滞后

| 项 | `novel-downloader`（主） | `novel-crawler`（对外） |
|---|---|---|
| 可见性 / 体积 | public / 24.6 MB | public / 297 KB |
| README | **无** | 有 |
| CONTRIBUTING | **无** | 有 |
| 仓库描述 | 空 | 有（topics: `crawler`, `python`） |
| `novelbase/sources/` | 10 个书源（扁平化后一层结构） | 只有旧结构的 `fanqie` |
| Android 套壳 | v4.5.1 已整体删除 | `android/` **仍在** |
| 最后推送 | 2026-09-30 | 2026-09-24 |

也就是说：**你给世界的那个版本，停在 2026-09-24（落后主仓库数十个提交），还包含一个你已经放弃的技术方案**（Chaquopy 套壳）。

#### ⚠️ 不一致 C：迁移白名单/黑名单已失效

`PUBLIC_MANIFEST.md` 与 `pyproject.toml` 的 `[tool.novel-downloader.migration] exclude`（文件自称「`check_public.py` 的唯一数据源」）里的排除路径仍是**扁平化之前**的形式：`novelbase/sources/qidian/**`、`novelbase/sources/qimao/**`、`novelbase/sources/92xs/**`、`novelbase/sources/fanqie/api/rain/**`。

实际目录早已是一层结构（`qidian_requests_default/` 等）。`scripts/check_public.py` 按清单做路径匹配 → **路径不存在 = 命中不到 = 不报错也不拦截**。因此现在执行迁移，会把红名单书源整批复制进 public。

（这条已同步进跨会话 background memory：`project/public-migration-exclude-stale.md`。）

### 1.3 合规基线（决定后面所有优先级）

按「不碰破解 / DRM / 付费绕过 / 恶意反爬」的边界如实评估：

- 内置书源指向的业务方中，**起点中文网、番茄小说、七猫免费小说**的内容以**授权付费 / 平台自有版权**为主；**92xs** 一类聚合站的合法性更弱。抓取 VIP / 付费章节会同时触及《著作权法》与平台 ToS。
- `api` 类书源（`fanqie_api_rain`、`qimao_api_rain`）走 **Rain.ink 第三方代理 API**，`fanqie_api_oiapi` 走 oiapi —— 属于经第三方间接获取平台内容，**仍然是绕过平台前端**，不因「没有直接爬」而免责。这也是它们出厂 `enabled: false`、且被排除出 public 的原因。
- **个人自用 + 不传播**：现实风险低。**公开分发 + 带宣传的开源项目**：风险显著（DMCA / 律师函 / 仓库投诉下架 / 账号连带风险）。
- **合规出路不是删功能，而是分层**：core 与书源在法律与架构上分开；官方源只做**公共领域 / 官方开放 API / 用户自有内容**（本地 EPUB 导入），其余作为**用户自带的扩展点**。

## 3. Top 5 最值得做

| # | 方向 | 理由 |

| 1 | **H1 + H2**（README/元数据 + 可见性决断） | 核心问题不是「缺功能」而是「没人知道它存在，且它的可见性状态与自己以为的不一样」。改动最小、收益最大，且是其余一切的前置 |

## 5. 最小可行 MVP

**MVP = 「让这个项目在合规前提下，被陌生人看懂并能跑起来」**，不是加功能：

1. **决断可见性**（半天）：主仓库转 private，还是公开并清源 —— 必须先定，否则后面全是白做
2. **主仓库 README + 仓库描述 + topics**（1 天）：一张界面上手截图 + 「它做什么 / 不做什么」+ 边界声明。可复用 `docs/` 的 30 多篇文档与 `novel-crawler` 的 README
3. **修迁移排除清单**（10 分钟）：`PUBLIC_MANIFEST.md` 与 `pyproject.toml` 的 exclude 仍是扁平化前路径，`check_public.py` 现在命中不到红名单目录 —— 这是**已存在**的漏洞
4. **一个合规示范源跑通闭环**（1-2 天）：用 Project Gutenberg 或公版中文书，证明「搜索 → 下载 → 入库 → 导出 EPUB → OPDS 取走」这条路干净且完整

这四件完成后，你就有了一个**能拿出手、能解释、不怕被问**的东西。之后的功能（校验 / 追更 / OPDS）才有意义。

## 7. 合规边界声明

本报告的全部建议遵守以下边界，**不包含也不建议**：

- 侵犯版权、绕过 DRM、破解付费内容、恶意反爬、规避平台限制
- 任何以「采集」为目的的方案，只建议：**合法授权内容 / 公共领域作品 / 用户自有内容 / 官方开放 API**，并遵守目标站点 `robots.txt` 与 ToS

对项目现状的如实提示见 [§1.3](#13-合规基线决定后面所有优先级)。
